# Security Policy

## Reporting a Vulnerability

As a curated list of security resources, Awesome LLMSecOps itself does not contain executable code. However, we take the integrity and safety of this repository seriously.

### If You Find a Security Issue

If you discover a security concern related to this repository (e.g., a linked resource that has been compromised, a link pointing to a malicious site, or a supply chain concern with a listed tool), please report it responsibly:

**🔒 For sensitive security issues:**

Email: **[awesome-llmsecops@proton.me](mailto:awesome-llmsecops@proton.me)**

Please include:
- Description of the security concern
- The specific resource(s) affected
- Steps to reproduce or verify the issue
- Any suggested remediation

**⏱️ Response Time:**
- We will acknowledge your report within **48 hours**
- We will investigate and respond with a plan within **7 days**
- Critical issues (malicious links, compromised resources) will be addressed within **24 hours**

### For Non-Sensitive Issues

If the issue is not sensitive (e.g., a broken link, outdated resource, or minor correction), please [open a regular issue](https://github.com/ARUNAGIRINATHAN-K/awesome-llmsecops/issues/new).

## Scope

This security policy covers:

- **Linked resources** — If a tool, framework, or resource listed in this repository is found to be compromised, malicious, or poses a security risk to users
- **Repository integrity** — Unauthorized modifications, compromised contributor accounts, or supply chain attacks targeting this repository
- **Social engineering** — Attempts to add malicious links or resources through deceptive pull requests

## Our Commitments

- We validate all linked resources before inclusion
- We periodically audit existing links for integrity
- We promptly remove resources found to be compromised
- We maintain transparency about any security incidents affecting listed resources

## Responsible Disclosure

We follow responsible disclosure practices. If a listed tool or framework has a security vulnerability:

1. **Do not** disclose the vulnerability publicly in our issues or discussions
2. **Do** report it to the affected project's security team first
3. **Do** notify us so we can add appropriate warnings or remove the resource
4. **Do** allow reasonable time for the affected project to patch before public disclosure

---

Thank you for helping keep the LLMSecOps community safe! 🛡️
